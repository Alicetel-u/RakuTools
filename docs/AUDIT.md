# 調査・検証記録（2026-11-19 JST）

## 結論

ギガファイル便の通常のブラウザ送信方式に相当する単発の小容量送信は動作しました。ただし、第三者向けサービスとしてその方式を継続利用できることと、RakuToolsの本番アップロードが動くことは未確認です。公開ページは準備中として提供し、送信を停止します。

## 既存実装で見つかった問題と対応

| 問題 | 対応 |
| --- | --- |
| 非公式仕様・利用条件未確認でもURL設定だけで送信可能 | サーバー側の連携確認フラグと全安全設定が揃うまで拒否 |
| CORS以外に認証・利用量制限なし | Turnstileのsuccess/hostname/actionを検証、接続元ハッシュ・Origin・秘密トークンでセッションを認証 |
| 利用者がmultipart内のID・サイズ・保存期間等を任意指定 | セッション作成時に検査・固定し、Workerがmultipartを生成 |
| Content-Lengthだけの検査 | 読み取り中の実バイト数を上限検査。空ファイルも対応 |
| 毎チャンク、現在の送信先HTMLを再取得・比較 | セッション作成時に固定。途中で送信先が変わって壊れる設計を修正 |
| 総量・ファイル数の制限なし | 1ファイル/1回合計10 GiB、20個。IP別10 GiB/40個/10回、全体50 GiB/200個/UTC日。開始間隔10秒 |
| 再送で二重アップロードの可能性 | 送信済み結果をキャッシュし直前チャンクの再要求は上流へ再送しない。送信前に結果不明状態を保存 |
| 通信失敗時に「未送信」と断言 | 結果不明を明示。自動再送しない。成功済みリンクを残し、選択欄から成功分を除く |
| 分割完了時にしか進捗更新しない | XHR uploadイベントでクライアント→Worker送信を実測。上流確認が終わるまで100%にしない |
| 保存期間を送信途中でも変更可能 | 送信中は設定・ファイル操作を固定 |
| 前回の進捗残存、ステップ表示未更新 | 毎回初期化、操作段階・部分成功を表示 |
| 公開成果物にworkerや文書まで含まれる | distへの許可リスト方式で公開ファイルだけ出力 |
| Pages未作成でActionsによる有効化が権限エラー | 認証済みGitHub CLIでPagesを作成し、Actionsはデプロイに専念 |

CORSだけでは不正使用は防げません。分散IPによる濫用や無料枠消費攻撃を完全に防ぐ保証はありません。公開前の負荷試験とCloudflareのトラフィック制御・予算/無料枠監視が必要です。

## 実際に確認したこと

1. 公式トップページから通常公開のアップロード先を取得。
2. 個人情報を含まない検証用テキスト1個を`upload_chunk.php`へPOST。HTTP 200 / status=0 / 共有URL発行を確認。UA・Origin・Refererの偽装なし。
3. 初回のセッションなしダウンロードはHTTP 200の案内HTMLで、実ファイルではありませんでした。HTTP 200だけを成功基準にしていません。
4. 発行された共有ページを通常GETし、そこで発行されたセッションCookieを保持して通常のdownload.phpへアクセス。application/octet-streamとなり、送信内容との一致を確認。Cookieや認証値の偽造なし。
5. 発行された削除キーで、この作業で作成した検証ファイルを削除。status=0を確認。
6. Nodeの17件の自動テスト：サイズ、空ファイル、分割、部分成功、中止、URL注入防止、セッション認証、重複防止、上流異常、利用量制限、送信処理→Worker結合試験。外部サービスはモック。
7. wrangler deploy --dry-runでバンドルを確認。実workerdでも起動・health・送信停止503・Origin拒否403・preflightを確認。
8. ブラウザでPC/390px幅の画面、複数ファイル選択、個別削除、全解除、保存期間変更、準備中のボタン無効を確認。

## 未検証・未解決

- Cloudflare本番Workerのデプロイと認証情報。ローカル環境は未ログイン、GitHubのCloudflare secrets/variablesも未設定でした。
- 直接連携を第三者サービスとして提供することの可否・名称使用・許容負荷。
- 本番RakuTools→Cloudflare→ギガファイル便→受信ダウンロードの一連の操作。
- Turnstile実キーを用いた本番での動作・拒否検証。
- 実サービスでの複数チャンク・複数ファイル・大容量・長時間送信・日付またぎ・携帯回線でIPが変わる場合の動作。
- スマートフォン実機。確認済みはデスクトップブラウザの狭い表示幅のみ。
- ブラウザ上での有効化された完了画面・Clipboard API・通信中止の一連の検証。送信ロジックはモックで確認済みです。
- 中継のメモリ/CPU/同時接続の負荷試験。8 MiB分割でも同時実行数によりWorkersの128 MBメモリや無料CPU枠を超える可能性があります。
- Cloudflareの無料枠を使い切ると停止します。24時間無停止や完全無料の保証はありません。

## データの扱い

ファイル本体を永続化しません。各チャンクは最大8 MiBを一時的にメモリで扱い、上流へ送信します。セッションにはファイル名・サイズ・上流送信ID・保存期間・共有URL・削除キー・認証トークン・接続元のHMACを持ち、24時間で失効・削除アラームを予約します。利用量情報は日次更新し48時間以内の削除を予約します。削除はCloudflareのアラーム実行に依存します。ハッシュ化は完全な匿名化を保証しません。Cloudflare等のインフラ側のアクセスログ・保存条件は各社のポリシーに従います。アプリはファイル本体・URL・削除キーをログへ出力しません。
